# Figure 1: fixed-base single-state intervention

This standalone experiment asks whether one teacher-supervised update at a
student-visited state changes the distribution of later states, after matching
the *realized* immediate gain. It imports model loading, prompt rendering,
vLLM rollout and compact Student-TopK scoring from `BellmanOPD_analysis`, but
does not call an OPD trainer or compute any TA/CMT/LIFT score.

## Scientific protocol

1. Load one frozen teacher and one `theta_base` student checkpoint.
2. Before updating anything, collect all 300 candidate states from distinct
   Competition-MATH prompts and trajectories generated by `theta_base`.
3. Keep one BF16 snapshot of all base parameters. Every intervention starts
   from this exact snapshot and creates a fresh AdamW optimizer.
4. At `s_t = prompt + y_<t`, freeze `U_t` to Student Top-16 under `theta_base`.
   Gather teacher logits only at those IDs, conditionally normalize both
   categorical distributions on `U_t`, and minimize
   `D0 = KL(p_bar_theta || q_bar)` for exactly one AdamW step.
5. Generate eight independent pre-update and eight independent post-update
   continuations from the *same exact prefix* (`temperature=1`, `top_p=1`,
   horizon 128). The two branches use deterministic, disjoint seed sets.
6. Restore `theta_base` exactly. Only then score every descendant state from
   both branches using the restored base student and frozen teacher. Every
   state uses its own Student-Top16 support under `theta_base`; `s_t` itself is
   excluded.
7. Record `Delta_immediate = D0-D1` and
   `Delta_future = F_before-F_after`. Figure 1 highlights the Q45--Q55
   immediate-gain band and reports Q40--Q60 as sensitivity analysis.

This is a checkpoint-local categorical intervention diagnostic. It does not
claim to equal the full neural-parameter causal effect of a token update.

## Outputs and resume

Each run writes:

- `resolved_config.yaml` and `resolved_config.json`;
- `environment.json`;
- `candidate_states.jsonl` (the pool is completed before intervention 0);
- `interventions.jsonl` (atomic append, one committed intervention per row);
- `continuations.jsonl.gz` (raw tokens plus descendant quality values);
- `summary.json`, `progress.log`, `figure1_caption.txt`;
- `figure1.png` (320 dpi) and vector `figure1.pdf`;
- TensorBoard events under `tensorboard/`.

Re-run with the same `RUN_NAME` (or `OUTPUT_DIR`) to resume. Completed
intervention IDs are skipped and never rewritten. Audit records from a crash
before the matching intervention commit are removed automatically.

Optional controls include `MATCHED_QUANTILE_LOW/HIGH`,
`SENSITIVITY_QUANTILE_LOW/HIGH`, `CANDIDATE_ROLLOUT_HORIZON`,
`CANDIDATE_COLLECTION_BATCH_SIZE`, and the model/data path variables shown in
the launcher. Resume rejects any changed scientific setting.

## Canonical one-B200 run

```bash
cd /workspace/storage-shared/nlp/minhpn19/Experiment

MAIN_REPO=/workspace/storage-shared/nlp/minhpn19/BellmanOPD_analysis \
CUDA_VISIBLE_DEVICES=0 \
NUM_STATES=300 K_ROLLOUTS=8 FUTURE_HORIZON=128 \
TOP_K=16 LEARNING_RATE=5e-6 SEED=42 \
ROLLOUT_VLLM_GPU_MEMORY_UTILIZATION=0.60 \
ROLLOUT_VLLM_MAX_MODEL_LEN=5500 \
  bash scripts/run_qwen3_4b_to_1p7b_compmath.sh
```

The launcher defaults to:

- teacher: `/workspace/storage-shared/models/Qwen3-4B`;
- student: `/workspace/storage-shared/nlp/tungdd11/stable-on-policy-distillation/OPD/model/Qwen3-1.7B-Base`;
- data: `/workspace/storage-shared/nlp/minhpn19/data/competition_math/data/train-00000-of-00001.parquet`;
- field `problem`, shared student tokenizer and `enable_thinking=false`.
